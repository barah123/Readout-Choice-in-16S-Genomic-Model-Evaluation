# Phase 7 — two extension studies, pre-registered

**Written 2026-11-08, before any Phase 7 data was fetched or any Phase 7 analysis was run.**

Phase 6 closed Protocol 3 with five named limitations. This phase addresses the two that are
both cheap and scientifically load-bearing. The other three (newer models, more tasks,
intermediate layers) are deferred with reasons given in §3.

---

## Extension A — do the models help on genuinely hard problems?

### Why

Phase 6's diagnostic A found that **half the locked-test blocks were saturated** (classical
error below 1%), so no method could possibly differ on them. Restricted to the 5 genuinely
hard blocks, the difference was +0.0026 with a wide interval [−0.0046, +0.0120], and the
model advantage **increased with difficulty** (Spearman ρ = +0.595, p = 0.006).

That observation was made *after* seeing the results, on 5 blocks. It is a hypothesis, not a
finding. Extension A tests it properly.

### Status of prior data

Every block used in Phases 2–6 is now **development data** for this question — the hypothesis
was generated by looking at them. Extension A therefore requires newly collected panels,
screened and analysed under this plan.

### Hypothesis (directional, declared in advance)

> On panels where k-mer counting is genuinely challenged (classification error > 5%), frozen
> genomic language model representations achieve **higher** balanced accuracy than k-mer
> counting.

Phase 5 found equivalence pooled across all difficulties. H1 here is that restricting to hard
panels reveals an advantage that pooling hid.

### Panel screening — selection uses CLASSICAL METHODS ONLY

Candidate panels are screened before full data collection, using a cheap sample
(`retmax=100` per species). A panel is **selected as hard** if, at its best region:

1. the observed-sequence ambiguity ceiling is ≤ 0.97, **and**
2. the k-mer + linear probe cross-validated balanced accuracy is ≤ 0.95
   (i.e. classical error ≥ 5%).

**No genomic language model is involved in screening.** Selection depends only on properties
of the sequences and on the classical comparator, so it cannot favour the models. This is the
critical design property: screening on difficulty is legitimate, screening on model
performance would not be.

Panels failing the screen are recorded and reported, not silently discarded.

### Analysis

Identical to the frozen Phase 3 plan, re-used without modification:
- same four checkpoints, same pooling, same R2 linear probe;
- isolate-grouped 5-fold CV, region chosen support-only and applied to both arms;
- primary estimand **DNABERT-2:R2 − C_kmer**, paired over selected hard panels;
- bootstrap 2000 draws, seed 1729, 95% percentile CI.

### Decision rule

Because H1 is now **directional** (models better on hard panels), the primary test is a
superiority test, not an equivalence test:

- CI entirely above 0 → hypothesis supported; the Phase 5 equivalence is difficulty-dependent.
- CI containing 0 → hypothesis not supported; Phase 5's equivalence extends to hard panels.
- CI entirely below 0 → models are worse on hard panels.

**Target: ≥12 selected hard panels.** Phase 6's hard-stratum SD was ~0.010; 12 panels gives a
CI half-width near 0.006. Fewer than 8 selected → reported as underpowered.

### Pre-committed honesty clause

If the result is "CI contains 0", that is the reportable finding and the Phase 6 correlation
will be described as **not replicated**. No post-hoc regrouping of panels will be used to
rescue it.

## Extension B — does the conclusion survive realistic, imperfect sequences?

### Why

Every result so far used clean reference sequences. Real 16S data carries sequencing errors,
imperfect primer binding that truncates the read, and the fact that one genome often contains
several slightly different copies of the gene. Protocol §17.5 lists this as a bounded
follow-up to run **after** the clean-data result is stable. It now is.

### Design

A sensitivity analysis of the Phase 5 primary contrast, run on the Phase 5 locked-test
panels. **Exploratory** — it re-uses data already unsealed, so it tests the robustness of an
existing conclusion rather than establishing a new one.

Perturbations applied to the extracted sequence of every isolate, independently per condition:

| condition | what it simulates |
|---|---|
| `clean` | baseline (reproduces Phase 5) |
| `err_0.1%` | high-quality Illumina substitution rate |
| `err_1%` | poor-quality run / degraded sample |
| `trim_10` | imperfect primer binding, 10 bases lost each end |
| `copy_var` | intragenomic copy variation: 1–3 substitutions per isolate |
| `combined` | `err_1%` + `trim_10` together |

Substitutions are uniform random base changes at the stated rate, seed fixed at 0. Both arms
receive **identical** perturbed sequences, so no arm is advantaged.

### What would change the conclusion

- Both arms degrade together, delta stable → Phase 5's equivalence is robust.
- k-mer degrades faster than the models → the models have a practical advantage on real data
  that clean-sequence benchmarking hides. This would be the most consequential possible
  outcome of Phase 7.
- The models degrade faster → their apparent parity depends on idealised input.

### Scope limit, stated in advance

Uniform random substitution is a crude error model. It is a stress test, not a simulation of
real PCR and sequencing artefacts, and will be described as such.

## 3. Deferred, with reasons

- **Intermediate layers.** DNABERT-2/DNABERT-S run their encoder on unpadded sequences
  internally, so extracting intermediate layers requires reproducing their unpad/repad index
  logic. Doing that wrong yields a silently incorrect representation. Deferred until it can be
  validated against the model's own final-layer output as a correctness check. HyenaDNA and
  NTv2 use standard interfaces and could be done first, cheaply.
- **Newer/larger models.** Phase 2-full showed model choice matters ~30× less than readout
  choice. Adding models before the readout question is settled would likely add cost without
  information, and several candidates need a GPU this machine does not have.
- **Additional tasks.** The region-ranking task (T2) is defined in the protocol and partially
  implemented; open-set rejection needs a separate unknown-taxon dataset. Both are worthwhile
  but neither addresses a limitation that currently threatens the main conclusion.

## Amendment A-1 — screening round 2 (logged 2026-11-08, before any model result on these panels)

**Change:** re-screen the 11 round-1 candidates that returned INSUFFICIENT DATA using
`retmax=300` instead of `retmax=100`, and add 12 new candidates of the type round 1 found
reliably hard (subspecies and tight species complexes).

**Reason:** round 1 selected only 5 hard panels, below the pre-set minimum of 8. But 11 of
the 30 candidates failed on *insufficient data at the cheap screening sample*, not on
difficulty — a data-collection shortfall. The original plan explicitly described the screen
as "a cheap sample (`retmax=100`)" with a full fetch to follow, so deepening it completes the
screen rather than altering it.

**What is NOT changed:** the selection criteria (ceiling ≤ 0.97 AND k-mer ≤ 0.95), the
classical-only screening rule, the primary endpoint, the analysis, and the ≥12 / <8 power
thresholds all stand exactly as written.

**Contamination check:** screening uses no genomic language model, and no model has been run
on any round-1 or round-2 candidate panel. Nothing about model performance has influenced
this amendment.

**If the total is still below 8:** Extension A is reported as underpowered, as pre-committed.

## Extension C — are intermediate layers better than the final layer?

**Pre-registered 2026-11-08, before any layer sweep was run.**

### Why this is required, not optional

The project's headline methodological claim is that *how you read a model* matters ~30× more
than *which model* you use. Every result so far used the **final layer only**. That is a
direct internal tension: a reviewer can reasonably say the conclusion is itself
readout-limited. Phase 6 deferred this because DNABERT-2/DNABERT-S store intermediate layers
in an unpadded internal format and extracting them risked a silently wrong representation.

HyenaDNA and NTv2 use standard interfaces. Both were probed before pre-registering, and both
pass the mandatory correctness check: **the extracted final layer is numerically identical to
the standard forward pass output** (`torch.allclose`, atol 1e-6). HyenaDNA exposes 10 layer
outputs, NTv2 exposes 30.

### Scope

Two of four models. DNABERT-2 and DNABERT-S remain untested and will continue to be reported
as a limitation. Testing half the models does not settle the question, but it converts "we
did not look" into "we looked where we safely could, and here is what we found."

### Design

- **Panels:** the 13 screened-hard panels. Chosen because they are the only set with
  meaningful headroom — the locked-test panels are mostly saturated, so no layer could show
  an advantage there.
- **Layers:** 5 evenly spaced depths per model, always including the final layer, so the
  frozen result appears as one point on the curve and acts as an internal control.
- **Everything else frozen:** same masked-mean pooling, same linear probe, same
  isolate-grouped 5-fold CV, same seed. Only the layer changes.
- **Correctness gate, enforced in code:** the run aborts unless the extracted final layer
  reproduces the standard forward output.

### Declared outcomes

1. **Final layer is best or tied** → the frozen choice was right; the readout claim stands and
   the layer limitation is substantially retired for these two models.
2. **An intermediate layer is clearly better** → *strengthens* the readout thesis (readout
   choice matters even more than reported), but means the main comparison understated the
   models. The equivalence result would need re-running with the better layer before the
   paper's central claim could stand.
3. **Differences are small and noisy** → layer choice is a minor factor relative to the
   readout-type effect already measured.

### Pre-committed

Outcome 2 is the one that would cost the most work, and it will be reported and acted on if
it occurs. No layer will be selected using the hard-panel results and then presented as if it
had been chosen in advance.
